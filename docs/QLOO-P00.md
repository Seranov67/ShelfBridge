# Підготовка P00 · 5 жовтня 2026

Оновлення 6 жовтня: реальний CLI P00 успішно виконав усі 13 контролів,
включно з 10/10 непорожніми профілями, двома непересічними полицями та
виключенням фактично рекомендованої книги. Перевірено 29/30 творів і всі
26 доступних книг. Доказ — `test-results/p00.json`, прив'язаний до поточного
review та каталогу. Контракт схвалено локально після перегляду результатів.
Повний Qloo/OpenAI-сценарій ще заблокований балансом OpenAI та денним лімітом.
Нижче збережено інструкції й попередній стан підготовки.

`npm run qloo:p00` у режимах `plan`, `exclude`, `replay` готує контрольні
запити та перевіряє локально збережені відповіді без API й без ключа.
Окремий режим `live` виконує обмежені реальні контролі через підтримуваний CLI;
його не слід плутати з офлайн-перевіркою.

## Підтримуваний доступ

Станом на перевірку 5 жовтня офіційний
[Qloo Hackathon Kit](https://github.com/qloo/qloo-hackathon-kit) вимагає
Node 22.19.0+ та `@qloo/qloo-harness` 0.1.26+. Для події підтримуються
`qloo explore`, `qloo exec`, `qloo api`, `qloo mcp`;
[умови доступу](https://github.com/qloo/qloo-hackathon-kit/blob/main/docs/API_ACCESS.md)
вимагають виданого організаторами credential або схваленого gateway.

Спочатку локально був Node 22.17.1 без harness. Суддівський прохід підготував
ізольований Node 22.23.3 і harness 0.1.26; `qloo:doctor` та `test:cli`
проходять. `QLOO_API_KEY` не налаштований. Деталі: [QLOO-CLI.md](QLOO-CLI.md).
Старий HTTP-адаптер не стає сумісним із доступом події лише через наявність
UUID або успішний локальний replay.

[Офіційний CLI-приклад](https://github.com/qloo/qloo-hackathon-kit/blob/main/starter/cli-workflow/README.md)
документує початкову перевірку пошуку:

```sh
qloo api search --query "Agatha Christie" --type book --take 3 --json --dry-run
```

`--dry-run` не викликає Qloo. Після налаштування підтримуваного доступу та квоти
можна виконати один реальний пошук без цього прапорця. Credential задається
через `qloo setup --qloo` або серверне середовище, не через аргумент `--api-key`.
Не запускайте платний пошук одночасно із ShelfBridge: ручний виклик harness
не входить до локального ledger нашого застосунку.

## План контрольних запитів

1. Скопіюйте `data/qloo-review.example.json` до `data/qloo-review.json`.
2. Перевірте реальні назви, авторів, типи й UUID. Не заповнюйте невідомі ID
   демонстраційними UUID. Залишайте непідтверджені записи без схвалення.
3. Виконайте:

```sh
npm run mapping:compile -- data/qloo-review.json
npm run qloo:p00 -- plan data/qloo-review.json
```

План зберігається у `test-results/qloo-p00-plan.json`. Неповний review повертає
`blocked`, код завершення 1 і порожній список запитів. Поріг 24/30 зіставлених
творів не скасовує вимогу зіставити кожну доступну книгу; потрібні всі
10 вручну перевірених профілів.

Повний план містить 12 готових запитів: `shelf-a`, `shelf-b`, `T01`–`T10`.
Дві полиці не перетинаються й разом охоплюють 26 доступних творів поточного
каталогу. Профілі зберігають оголошені бюджети та недоступні книги.
Тринадцятий запит `exclude-first` залежить від першого фактичного результату
`shelf-a`: ця книга забирається з усіх допустимих видань, смаки зберігаються.
Після збереження фактичної відповіді `shelf-a` у captures виконайте:

```sh
npm run qloo:p00 -- exclude data/qloo-review.json test-results/qloo-captures.json
```

Команда звіряє першу відповідь і записує точний залежний запит у
`test-results/qloo-p00-exclude.json`. До отримання `shelf-a` не обирайте книгу
для контролю навмання. Після його виконання додайте відповідь `exclude-first`
до того самого captures-файлу.

`method`, `path` і `params` описують канонічний запит застосунку. CLI-адаптер
перетворює його на `qloo api insights --params … --json`; точні параметри
перевірені з реальним harness і локальним контрольованим upstream. Збіг із
реальним доступом події ще потребує P00. Не перемикайте endpoint чи credential
автоматично при помилці доступу.

## Перевірка збережених відповідей

Файл captures — JSON-масив максимум із 13 записів такого формату:

```json
[
  {
    "id": "shelf-a",
    "method": "GET",
    "path": "/v2/insights",
    "params": {},
    "response": { "results": { "entities": [] } }
  }
]
```

Порожні `params` тут показують лише структуру. Для справжньої перевірки
скопіюйте точні параметри відповідного запиту з плану та його мінімальну
відповідь. Зберігайте тільки `results.entities[].entity_id`; ключі, заголовки,
сирі повідомлення помилок та повний граф до captures не додавайте. Зберігайте
файл локально в `test-results/`, яка ігнорується Git.

```sh
npm run qloo:p00 -- replay data/qloo-review.json test-results/qloo-captures.json
```

Replay перевіряє збіг запиту, структуру HTTP-відповіді, дозволену полицю,
повторні UUID без урахування регістру та контроль виключення. Для проходження
потрібні всі 13 валідних відповідей, 3 непорожні контролі та ≥8/10 непорожніх
профілів. Відсутні чи невалідні відповіді не зараховуються як допустиме
порожнє покриття. Поля affinity та довільний текст не потрапляють у звіт.

`test-results/qloo-p00-replay.json` завжди має `source=offline_replay`,
`liveQlooVerified=false`, `contractApproved=false`, навіть якщо `state=passed`.
Парсер у `src/qloo-contract.mjs` спільний для CLI та старого HTTP-адаптера.
Фактичний `qloo api … --json` у harness 0.1.26 повертає масив сутностей;
CLI-адаптер обгортає його в наведений envelope. Локальні captures зберігають
саме цю мінімальну обгортку. Workflow-результати `qloo exec` чи MCP не можна
підставляти замість перевіреної відповіді CLI.

## Докази й наступний live-прохід

План містить SHA-256 fingerprint каталогу, зіставлень, профілів і контрольних
запитів. `npm run preflight` відновлює план із поточного
`data/qloo-review.json`, звіряє активний `data/qloo-mapping.json` та вимагає
повний P00-звіт. Скорочене `state=passed`, інший fingerprint, fixture/replay
або некоректні результати не підтверджують P00. Старі скорочені P00-звіти
потрібно перевірити повторно. Це локальні докази оператора, а не підписана
атестація походження відповідей.

Підтримуваний адаптер і live-збирач тепер реалізовані й локально перевірені.
Після отримання credential та reviewed ідентичностей зупиніть застосунок і
виконайте `npm run qloo:p00 -- live data/qloo-review.json`: максимум 13 запитів,
120 секунд загалом, спільні lock/ledger, зупинка після першої помилки.
Команда зберігає мінімальний `test-results/p00.json` із транспортом `cli`,
повними контрольними результатами й поточним fingerprint. Прапорець контракту
сама не вмикає. Не перейменовуйте офлайн-звіт у live-доказ.

Поточні P00, реальний Qloo/LLM-сценарій, якість рекомендацій і публічний запуск
залишаються відкритими. Цим проходом зовнішні провайдери не викликалися.
