## Виконано

- Створено локальний `.env` із порожнім `QLOO_API_KEY`; fixture-режим і
  `QLOO_CONTRACT_APPROVED=false` збережено. Файл ігнорується Git/Docker.
- `npm run preflight` перевіряє конфігурацію, зіставлення, покриття та наявність
  позитивних live-доказів. Повертає ненульовий код, якщо інтеграція не готова.
  Навіть позитивна конфігурація сама по собі не означає готовність релізу.
- `npm run smoke:llm` зберігає лише дозволені категорії помилок. HTTP 429
  розрізняється за кодом/типом: баланс або квота, тимчасовий rate limit,
  невідома причина. Текст помилки провайдера та ключі не записуються.
- Сервер, probe і smoke використовують спільне блокування runtime з PID та
  типом операції. Одночасний запис бюджету заборонено; помилки звільняють lock.
- `data/qloo-review.example.json` містить 30 книг із авторами та 10 профілів.
  Усі Qloo ID залишені порожніми. `npm run mapping:compile -- data/qloo-review.json`
  створить робочі зіставлення лише після явного перегляду ідентичностей,
  перевірки типів, унікальності, узгодженості та повноти доступної полиці.
  Компіляція не підтверджує контракт Qloo.
- `npm run evaluate:fixture` виконує всі 12 оголошених сценаріїв, 10 уточнень
  і 2 випадки без залишків. **0 порушень жорстких обмежень.** Це поведінкова
  перевірка демонстрації, не порівняльний benchmark якості рекомендацій.
- Підготовлено `compose.yaml`: один сервіс, локальний порт, постійний runtime-том
  і healthcheck. Docker відсутній у доступному PATH; контейнер не запускався,
  перевірка Docker Compose не виконувалася. Публікації не було.

## Реальна перевірка OpenAI

4 жовтня 2026, 15:56 за Києвом: один виклик із наявним серверним ключем,
модель `gpt-4.1-mini`, без повторів. API повернув `credit_balance_exhausted`.
За [OpenAI Docs](https://developers.openai.com/api/docs/guides/error-codes)
цей код означає вичерпаний передплачений баланс організації. Повтор запиту
без зміни балансу не відновить доступ.

Потрібно поповнити баланс відповідної організації через
[OpenAI API Billing](https://platform.openai.com/settings/organization/billing/overview)
або налаштувати інший дозволений ключ із доступними кредитами.
Баланс чи платіжні налаштування автоматично не змінювалися.

Локальний сервер перезапущено й перевірено: `/api/health` повернув 200,
`mode=fixture`. Лічильник спільного бюджету після smoke: 4 виклики за день
замість попередніх 3. Успішний LLM або Qloo результат не заявляється.

2. На [Resources](https://qloo.devpost.com/resources) відкрити
   **FIRST, get your API key here**.
3. Заповнити форму: email, ім'я, прізвище, Devpost username, країна,
   ідея проєкту; GitHub username необов'язковий. Прочитати умови перед згодою.
4. Коли доступ буде видано, вставити ключ локально після `QLOO_API_KEY=` у

## Після отримання доступу

Актуальний [офіційний набір Qloo](https://github.com/qloo/qloo-hackathon-kit)
описує підтримувані для події CLI/MCP-поверхні. Йому потрібні Node 22.19+
та `@qloo/qloo-harness` 0.1.26+. Доступний локальний Node — 22.17.1;
harness не встановлювався. Наявний HTTP-адаптер ShelfBridge використовує
попередній endpoint та контракт, тому його сумісність із виданим доступом
ще належить перевірити. Автоматичного перемикання endpoint або ключів немає.

Послідовність наступного live-проходу:

1. Налаштувати підтримуваний доступ із виданим credential та перевірити
   readiness harness без мережі; потім зробити один обмежений пошук.
2. Перевірити реальну форму відповіді, точні назви/авторів, типи й UUID.
   Підготувати вручну переглянуті зіставлення та 10 профілів.
3. Виконати P00: дві непересічні полиці, виключення рекомендованої книги,
   усі 10 профілів. Ціль: ≥24/30 зіставлених творів і ≥8/10 непорожніх профілів;
   кожна книга, яку може обрати live-полиця, повинна мати підтверджене зіставлення.
4. Лише після позитивних контрольних результатів підтвердити контракт,
   повторити OpenAI smoke та перевірити повний сценарій із двома провайдерами.
5. Провести запланований B0/B1/B2/Full benchmark і реальні користувацькі
   завдання. Учасників не залучали; результатів людей ще немає.
6. Обрати хостинг, перевірити контейнер, HTTPS, постійний бюджет і зовнішній
   доступ. Provider spending limits та публічний репозиторій ще не підтверджені.
