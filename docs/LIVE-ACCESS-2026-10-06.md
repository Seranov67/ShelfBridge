# Реальний доступ · 6 жовтня 2026

Qloo працює через підтримуваний harness 0.1.26 та endpoint організаторів.
Повний режим із двома провайдерами ще не ввімкнений через баланс OpenAI.

## Підтверджено

- Перегляд метаданих 29/30 творів: назви, автори, роки, альтернативні видання.
  Зіставлено всі 26 творів, які може обрати доступна полиця.
- `priory` залишено без ID: обмежений пошук не дав точного збігу, залишок нульовий.
- Для Hitchhiker обрано перший роман, а не збірник, що стояв вище в результатах.
- `AURORA` був неоднозначним: MusicBrainz ID першого збігу ідентифікує Leanna
  Milward, попри суперечливий опис Qloo. Обрано окрему сутність `Aurora Aksnes`.
  [MusicBrainz підтверджує ім'я норвезької співачки](https://musicbrainz.org/artist/484a4e90-6899-4e4b-a948-a2255d365340).
- P00: 13/13 валідних відповідей, дві непересічні полиці, фактичне виключення
  першої рекомендованої книги, 10/10 непорожніх профілів. У контролях усі
  повернуті роботи належать відповідній дозволеній полиці.
- `QLOO_CONTRACT_APPROVED=true` встановлено лише після звірки поточного P00.
  `SHELFBRIDGE_MODE=fixture` збережено.
- Пошук книг тепер показує автора та рік із поля disambiguation, а підказка
  допомагає знайти норвезьку AURORA за повним ім'ям.
- Локальна перевірка: 88/88 Node-тестів та 23/23 fixture-браузерних сценаріїв,
  без JavaScript-помилок. Переглянуто знімок інтерфейсу з новою підказкою.

Перегляд ідентичностей виконав Codex за реальними метаданими; участь незалежного
людського рецензента чи оцінка якості рекомендацій не заявляється.

## Блокери

Новий реальний OpenAI smoke повернув HTTP 429 / `credit_balance_exhausted` /
`insufficient_quota`. Потрібно додати API-кредити для організації поточного
ключа або налаштувати дозволений ключ із доступним балансом.
[OpenAI Docs описує цю помилку й відновлення доступу](https://developers.openai.com/api/docs/guides/error-codes).
Платіжні налаштування не змінювалися, повторів після цієї помилки не було.

Ledger: 60/60 зарезервованих спроб за 6 жовтня UTC. Ліміт не підвищувався;
враховано невдалі sandbox-спроби та перевірку метаданих. Наступний день бюджету
починається 7 жовтня о 03:00 за Києвом (00:00 UTC). Пошук і P00 не треба
повторювати без зміни review/каталогу або нової проблеми.

## Завершення повного режиму

Після відновлення балансу та денного бюджету зупинити застосунок і виконати:

```sh
npm run smoke:llm
npm run smoke:live
npm run preflight
npm run enable:live
npm start
```

`smoke:live` вимагає успішний planner smoke, поточний P00, схвалений контракт
та щонайменше 14 доступних запитів. Це максимум: два пошуки та три цикли
рішень, кожен із до трьох OpenAI-викликів і одного Qloo ranking. Перевіряються
підтверджені смаки, відмова від книги, бюджет $15, картка, сесія та відсутність
provider-викликів за порожньої полиці. Режим самостійно не змінюється.

`enable:live` робить лише локальну зміну `.env` після успішних доказів.
Повний сценарій прив'язаний до model, review/P00 та SHA-256 поточного серверного
коду. Застарілий, неповний чи fixture/mock-звіт не проходить перевірку.
Наявний `.env` завжди залишається локальним. Перевірити, що успадковані змінні
оточення процесу не перекривають новий ключ у `.env`.

Реальні людські оцінки, публічний репозиторій, HTTPS-хостинг і provider spending
limits залишаються окремими релізними кроками. Benchmark підготовлено без
provider-викликів; людських результатів або підвищення якості не вигадано.
